## Subroutines
- If subroutines are to be used, dependent fields must be listed in pipe-delimited lists, eg:
  - Subroutines: name_parser, gender_estimate
-	SrStep: Subroutines will be run in the order they are pesented at the point detemined by the Step number
  - Step 1 - takes place after the initial reading of the input file, on the whole file. Requires InFields labels
  - Step 2 - takes place on the batches of data, before they are submitted to the Refiner API
  - Step 3 - after the Refiner API result has been returned, but before it is written to the file.

_SrArguments: FullName, FullName|Title_

would send the field FullName to the name_parser subroutine and the fields FullName & Title to gender_estimate

      Subroutines: filter_na,count_rows,check_addresses
      SrStep: 1,1,2
      SrArguments: [InAddressFields],unused,[InAddressFields]

## Notes 
###	Subroutines:
-	check_layout - checks to ensure correct number of columns, data type of each column and column headings (dependent on HeaderStyle)
-	filter_na - removes records with empty address fields
-	count_rows - counts the number of lines in the supply file
-	dedupe - dedupes the entire file based on the fields specified. Enter '-' as the first Field to create an exclusion list (eg -|Title|Gender would select all input fields except Title & Gender)
-	sort - sorts the entire file based on the fields specified. Enter '-' as the first Field to create an exclusion list
-	name_parser - Splits a single name field into the required FirstName, LastName, MiddleName & Title. Remember to add these to the SasFields for mapping
-	forename_parser - Splits out a single first name field into the required FirstName and MiddleName. Remember to add these to the SasFields for mapping
-	gender_estimate - Estimates the gender of the subject based on the passed name fields
-	address_select - Chooses which address data to include if an incomplete record is returned from the Refiner API
